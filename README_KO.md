# 검사기 호환성 수정 — 키맵은 덮어쓰지 않습니다

## 원인
추가 검사기 `scripts/check_combo_boot.py`가 일반 마우스 콤보의 내부 이름
`mouse`를 필수로 요구했습니다. 이름 변경 또는 삭제 시 `Missing node: mouse`가
발생하는 것을 기존 파일로 재현했습니다. 오류가 마우스 하드웨어 고장을 의미하지는 않습니다.
GitHub 최신 파일은 조회되지 않아, 현재 저장소에서 이름이 바뀌었는지 삭제됐는지는
확정하지 않았습니다.

## 교체할 파일 (2개)
- `scripts/check_combo_boot.py`
- `tests/test_repository.py`

위 두 파일을 `Obrey/modu-c-zmk-obrey`의 **같은 경로**에 교체하고 커밋하세요.
현재 파일 두 개는 먼저 백업하세요. 저장소 루트에 다른 이름으로 올리지 마세요.
`config/modu.keymap`, `scripts/validate.py`, `build.yaml`, `.github/workflows/build.yml`,
`local-modules/obrey-combo-boot/`는 이번 수정 때문에 변경하지 않습니다.
이 README와 VALIDATION.json은 참고용이며 저장소에 올릴 필요 없습니다.
이 ZIP은 전체 저장소가 아닙니다. 기존 전체 저장소 위에서 두 파일만 교체합니다.

## 변경
일반 콤보의 이름/존재 여부, 일반 문자와 게임 조작키 위치를 고정하지 않습니다.
135/680 콤보와 사용자 정의 동작은 이름 대신 실제 키 위치와 연결된 동작으로 찾습니다.
관련 없는 mouse 콤보가 없어도 통과하지만, 부트로더 콤보가 없어지거나 잘못된 쪽을
가리키는 설정, stock &bootloader 직접 연결, 범위를 벗어나는 번호는 거부합니다.
Base에서만 활성화하는 조건, 80ms/300ms 설정, 콤보-입력 관찰 위치 일치,
숫자 1/3/5 및 6/8/0 대응, 모듈 로딩 경로 검사는 유지합니다.
원본 scripts/validate.py의 메타데이터/보드/빌드/패키징 검사는 그대로 실행됩니다.
부트로더 숫자 위치/시간 조건은 이 확장의 계약이므로 일반 키처럼 임의 변경하지 마세요.

테스트도 사용자의 현재 키맵을 시험용 원본으로 삼지 않도록 변경했습니다.
시험은 임시 폴더 안의 고정 예제에 대해 실행됩니다. 현재 실제 키맵은 앞 단계의
검사기가 따로 검사하며, 테스트가 현재 키맵 파일을 수정하지 않습니다.
원본 검사기에는 첫 두 레이어의 노드명 등 기존 규칙이 남아 있습니다.
이 수정이 모든 가능한 Devicetree 문법/에디터 출력 형식을 지원한다는 뜻은 아닙니다.

## 확인
첨부된 전체 저장소를 풀고 두 파일만 교체하여 Python 시험 48개를 통과했습니다.
원래 구성, mouse 이름 변경, mouse 삭제, 게임/기호 키 변경을 각각 적용한 사본에서
원본 검사 → 수정 검사 → Python 테스트 순서가 모두 통과했습니다.
기존 C 호스트 시험(모의 API) 및 HEX/UF2 자체시험도 통과했습니다.
실제 ZMK 펌웨어 컴파일/실물 시험은 하지 않았습니다.
이 파일들은 새 펌웨어나 UF2가 아니라 빌드 전 검사 코드의 수정입니다.
